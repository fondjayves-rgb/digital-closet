# Workshop 5.4 Step 1 — systematic testing checklist

Generated from the inspected current React pages/components, shared contracts, API/worker code and existing test assertions. The older [update-only checklist](workshop-5.4-testing-checklist.md) is historical context, not proof of this run.

**Scope:** every implemented page, entry point, button/link/icon control, form field, native menu option family, conditional dialog/action and meaningful read/write/retry/cancel workflow found in source. Repeated card/entry/component controls are parameterized by their ID/label; test each repeated instance with disposable data. Static branding and decorative illustrations are inventoried separately. There are no implemented password-reset/account-deletion menus, checkout, weather or deployment controls to invent.

**Status semantics:** Passed applies only to the stated steps and evidence boundary, not to all listed candidate inputs. Every additional boundary/fault/keyboard variant is queued in VAL/AX and option cases, and remains Not tested unless explicitly exercised. Blocked identifies an unmet prerequisite and the action needed. No manual UI, inbox or device check is marked Passed. New live service checks are separately labeled. A confirmed defect can be fixed/retested while its broader control matrix remains Not tested; see [bug log](workshop-5-4-bug-log.md).

**Current inventory:** 284 cases — 131 Passed; 147 Not tested; 0 Failed; 6 Blocked. Current evidence is in [next-phase results](workshop-5-4-phase2-results.json); [Step1 results](workshop-5-4-results.json) remain historical.

**Prerequisites and safety:** run isolated tests on port5174, never against personal records. For manual work use an account you control and uniquely named W54 TEST records; preserve all existing records. Refresh before retrying a timed-out write. Fixture persistence is in-memory backend persistence across browser reload, not a live Supabase result. Registration/inbox/provider/physical-device cases require the stated separate exercise. The Step1 live checks remain historical; this next phase has a separately labeled fresh live artifact. This audit does not assert that your configured credentials are missing; Blocked live cases need the stated separate controlled exercise. Repeat shared metadata fields in every hosting form, not just one instance.

[Browser sources](../tests/browser/), [local regression sources](../tests/), [feature map](feature-inventory.md). No new paid AI or hosted mutation is needed for these isolated checks.

**Next phase:** [Current results](workshop-5-4-phase2-results.json) record 65 isolated API/database/schema tests, 92 fixture Chrome checks and 17 live Supabase checks plus cleanup. New superseding case evidence below comes from these executed checks. The two Step1 fixes remain historical; [new defects and retests](workshop-5-4-bug-log.md) and [read-only security review](workshop-5-4-security-review.md) are separate.
