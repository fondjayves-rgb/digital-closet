Part 1: New AI Use Case — Problem Framing
369 words · Meets the required 300–400 words

Company Context and Current Challenges

LoopWear is a fictional circular-fashion e-commerce retailer that offers affordable everyday clothing and encourages customers to make better use of items they already own. Unlike my first application, HomeFlow, which focused on renter records and lease-related responsibilities, Wardrobe App addresses personal wardrobe organization and outfit planning. Shoppers may forget what is in their closets, buy similar garments unnecessarily, or spend too much time choosing outfits. For LoopWear, a useful wardrobe service could strengthen customer engagement without pushing purchases. These are business hypotheses that a pilot must validate.

Specific Business Problem

The central problem is that clothing information is fragmented between physical closets, shopping histories, camera galleries, and personal memory. Existing manual wardrobe catalogs require users to label every item, which can discourage consistent use. Wardrobe App will provide a private digital closet where users photograph garments, review AI-proposed labels, and request outfits using only clothing they actually own. It will not make purchases or claim to know a garment's size, material, or fit from an unclear image.

Target Users and Their Needs

The primary users are busy students, young professionals, and budget-conscious shoppers who want faster outfit decisions and better use of existing clothing. They need mobile-friendly uploading, searchable clothing categories, simple style preferences, occasion-based outfit ideas, and control over their photos. LoopWear's product team also needs aggregate, privacy-respecting evidence of whether users find the feature valuable; it will not see individual private wardrobes.

Why AI Is the Right Solution

AI is appropriate because image understanding can suggest clothing type and color, while a language model can explain combinations based on a user's preferences and confirmed inventory. However, AI will make proposals rather than decisions: users correct labels, and server-side rules verify that recommendations reference owned items. Conventional code handles authentication, ownership, data storage, filters, and saved outfits.

Success Metrics and MVP Features

The minimum viable product includes secure accounts, private garment-photo uploads, editable AI tags, wardrobe search and filters, three outfit suggestions per request, and a saved-outfit history. Proposed success targets are: at least 80% of 10 pilot testers complete photo upload, tag review, and outfit saving; at least 90% agreement on category and main color across 100 labeled test photos; 100% of suggested item IDs exist in that user's confirmed wardrobe; and zero unauthorized access in 50 cross-account tests. These are acceptance goals, not achieved results.

3. Key features
The five initial MVP feature groups are secure registration and sign-in, private clothing upload, reviewed AI garment recognition, searchable wardrobe inventory, and AI outfit generation with saving and wear history.

For garment recognition, AI will propose a category, color, pattern, and supported descriptive attributes. Users must approve or correct these before the item becomes active. For recommendations, the backend will provide AI with eligible, confirmed garments and validate every returned clothing ID before displaying an outfit.
4. Database structure
Wardrobe App will use eight principal PostgreSQL tables.
Table	Responsibility
profiles	Personal preferences and settings
wardrobe_items	Confirmed and draft garments
ai_tag_jobs	Image-processing jobs and statuses
tag_suggestions	AI-proposed descriptions awaiting review
outfits	Saved outfit records
outfit_items	Clothing assigned to each outfit
wear_logs	User-confirmed outfit usage
outfit_feedback	Ratings and feedback
Every user-owned record will be protected by ownership rules and Row Level Security. Backend checks will also reject attempts to associate another user's clothing with an outfit.

6. AWS Elastic Beanstalk deployment strategy
Elastic Beanstalk supports Docker-based web applications and manages the supporting AWS infrastructure. It does not have an additional service management fee, although underlying resources such as EC2 instances, load balancing, and storage are billed. Account permissions, quotas, and regional service availability will need to be confirmed.

The planned production deployment will work as follows:
1. Build the React frontend and Express API into a versioned Docker image.
2. Use GitHub Actions to run tests and push the image to Amazon ECR.
3. Create an Elastic Beanstalk Docker environment on Amazon Linux 2023.
4. Deploy the approved ECR image using a Dockerrun.aws.json v1 artifact and Elastic Beanstalk CLI.
5. Configure an Application Load Balancer, Auto Scaling, HTTPS certificate, and /health checks for production.
6. Store sensitive credentials in AWS Secrets Manager or Parameter Store with least-privilege access.
7. Configure SQS and Lambda to process AI image-analysis jobs separately from the web server.
8. Enable CloudWatch monitoring, deployment health checks, version rollback, and post-deployment testing.
AWS supports the ECR image deployment and load-balancer HTTPS arrangements described above.

7. Lessons from HomeFlow
HomeFlow's validation identified incomplete authentication, local persistence paths, unverified AI processing, and background tasks that did not yet have reliable scheduling infrastructure. HomeFlow_Assignment_1.4.docx


Wardrobe App will address these gaps by making real sign-in, cross-account isolation, database persistence, truthful AI processing status, and successfully saved outfits mandatory acceptance requirements before any MVP feature is declared complete.
